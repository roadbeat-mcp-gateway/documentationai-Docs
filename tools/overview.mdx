The gateway ships a fixed, code-reviewed catalog — no tools are loaded from elsewhere at runtime. Release 0.1.0 contains **55 tools**, **33 resources** (including templates), **4 prompts** and **3 skills**, plus the typed `studio_create_<type>` tools generated for your Studio organization.

## Endpoints (views)

| Endpoint | Serves | Good for |
|----------|--------|----------|
| `/mcp` | The **core** set: at most 20 everyday tools | Claude connectors, ChatGPT, Cursor |
| `/mcp/all` | Everything your account may use | Claude Code and clients with tool search |
| `/mcp/discovery` | [Discovery](/tools/discovery) tools and resources, the why-card | Research agents |
| `/mcp/schema` | [Schema Registry](/tools/schema-registry) | Developers, content modelling |
| `/mcp/cd` | [Goal catalog](/tools/goal-catalog) and [your goals, follows, bookmarks](/tools/personal-data) | Personal assistants |
| `/mcp/goals` | [Compass](/tools/compass) | Personal assistants |
| `/mcp/studio` | [Studio](/tools/studio), including the typed `studio_create_<type>` tools and `studio://` resources | Editors |

`/mcp/pod` and `/mcp/augmentor` exist but are empty in release 0.1.0 — the Content Pod and Augmentor servers follow later. `search`, `fetch` and the [gateway tools](/tools/gateway) are part of `/mcp` and `/mcp/all` only.

## Who sees which tools

Tools appear only when your account can use them:

| Signed in as | Core `/mcp` | Additionally on `/mcp/all` and server views |
|--------------|-------------|---------------------------------------------|
| Personal account (Web Client) | 13 tools | personal-data and Compass tools |
| Organization account (Studio) | 10 tools | Studio tools |
| Local sidecar | 13 tools | personal-data and Compass tools |
| Anonymous | 8 tools | public tools only (no data-rights tools) |

Operators can switch individual tools, resources and prompts off for their deployment; switched-off entries disappear from every view.

## Resources

Resources are read-only documents an app can attach as context. Templates (with `{…}`) stand for many concrete resources; apps list them with `resources/templates/list`. The core endpoint `/mcp` only serves `gateway://me` and `gateway://me/export` — every other resource is available on `/mcp/all` and on the view of its server (`discovery://` on `/mcp/discovery`, `schema://` on `/mcp/schema`, `cd://` on `/mcp/cd`, `studio://` on `/mcp/studio`).

## Conventions every tool follows

- **Structured results.** Every result has `structuredContent` (JSON, with an `outputSchema` where declared) and the same data as text for clients that only read text.
- **Untrusted content is marked.** Results containing publisher or user text carry `_meta["net.roadbeat/untrusted"]: true`.
- **Tool metadata.** Each tool carries `_meta["net.roadbeat/server"]` and `_meta["net.roadbeat/consentClass"]`, plus truthful `readOnlyHint`, `destructiveHint`, `idempotentHint` and `openWorldHint` annotations.
- **Stable order.** Lists are sorted by name and carry caching hints (`ttlMs`, `cacheScope: "private"`), so clients can cache the tool list.
- **Errors as results.** Expected failures (not found, invalid input, upstream unavailable) come back as tool results with `isError: true` and a sentence the assistant can act on.
